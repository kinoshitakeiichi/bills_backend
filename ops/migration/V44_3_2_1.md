# V44.3.2.1 Flyway/JPA circular dependency fix

The pre-Flyway base configuration contains:

```yaml
spring.jpa.defer-datasource-initialization: true
```

That setting is appropriate only when SQL initialization should run after Hibernate.

Once Flyway is the schema initializer, Spring Boot expects the opposite order:

```text
DataSource -> Flyway -> EntityManagerFactory / Hibernate validate
```

The `migration` profile therefore overrides the base value to:

```yaml
spring:
  jpa:
    defer-datasource-initialization: false
```

This package does not modify V1/V2/V3 migration SQL and does not create or alter
`flyway_schema_history` manually.
