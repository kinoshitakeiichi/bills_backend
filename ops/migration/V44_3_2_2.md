# V44.3.2.2 — V3 Japan calendar Flyway fix

Observed PostgreSQL/Flyway failure:

- migration: `V3__japan_business_calendar.sql`
- SQLSTATE: `42804`
- target: `b_business_calendar_days.calendar_date`
- target type: `date`
- source expression type: `text`

Cause: the `seed_day(... ) AS (VALUES ...)` CTE infers quoted date literals such as
`'2022-01-01'` as text. PostgreSQL does not implicitly assign that CTE text expression
to the DATE target column in this INSERT ... SELECT.

Fix:
- cast `s.calendar_date::date` at the INSERT SELECT boundary;
- remove explicit `BEGIN`/`COMMIT` because Flyway already executes this PostgreSQL
  migration transactionally.

No seed rows, IDs, holiday names, V1 baseline, or V2 master data are changed.
